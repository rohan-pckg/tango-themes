# Distributing through Package Control

**Short answer: this repository is not currently installable through Package
Control, and cannot be made so without a separate repository.**

This file explains why, and what to do about it.

## What Package Control actually supports

Package Control is the package manager for **Sublime Text only**. It has no
mechanism for Sublime Merge packages or themes, so there is nothing to prepare
on the Merge side — Sublime Merge is install-by-copy, full stop.

For Sublime Text, the default channel has one structural requirement that a
monorepo cannot satisfy:

> Use a public GitHub or BitBucket repository. **Only include one package per
> repository and be sure the root of the package is the root of the
> repository.**
> — [packagecontrol.io/docs/submitting_a_package](https://packagecontrol.io/docs/submitting_a_package)

There is no `subdirectory` key in the channel schema. A repository whose root
contains `colors/`, `sublime-text/` and `sublime-merge/` would install those
three folders as a Sublime Text package, which is meaningless.

## Option A — recommended: publish the Sublime Text theme as its own repository

Keep `tango-themes` as the monorepo of record and publish a second repository
whose root *is* the package:

```text
tango-sublime-text/            <- repository root, also the package root
├── Tango Neovim.sublime-color-scheme
├── README.md
├── LICENSE
├── .gitignore
└── package-metadata.json      <- generated by Package Control, never committed
```

Then fork [the Package Control channel](https://github.com/wbond/package_control_channel)
and add to `repository/<letter>/tango-sublime-text.json`:

```json
{
    "name": "Tango Neovim",
    "details": "https://github.com/rohan-pckg/tango-sublime-text",
    "releases": [
        {
            "sublime_text": "*",
            "tags": true
        }
    ]
}
```

Requirements before submitting:

1. **Semantic-version tags** (`v1.0.0`), one per release. Branch-based releases
   are deprecated and rejected.
2. **A declared license** — the MIT `LICENSE` in this repository.
3. **No `.pyc` files.
4. **No `package-metadata.json`** — Package Control generates it on install.
5. **Package name** must be ASCII, use CamelCase or `underscore_notation`, and
   must not contain `.`, `/`, `<`, `>`, `:`, `"`, `\`, `|`, `?` or `*`.
   `Tango Neovim` is safe (the space is allowed).
6. Because the color scheme references its own variables rather than external
   files, there are no hard-coded path references to check.
7. Run the *ChannelRepositoryTools: Test Default Channel* command locally
   before opening the pull request.

To keep the two repositories in sync, either make `tango-sublime-text` a git
subtree of this one, or add a small CI step that copies
`sublime-text/Tango Neovim.sublime-color-scheme` into the other repository on
tag.

## Option B — keep one repository, use a custom repository channel

If you want everything in a single repository you can host your own
`packages.json` and add it via **Package Control: Add Channel**:

```json
{
    "schema_version": "3.0.0",
    "packages": [
        {
            "name": "Tango Neovim",
            "details": "https://github.com/rohan-pckg/tango-themes",
            "releases": [
                {
                    "sublime_text": "*",
                    "url": "https://github.com/rohan-pckg/tango-themes/archive/refs/tags/v1.0.0.zip",
                    "version": "1.0.0"
                }
            ]
        }
    ]
}
```

Note that with a zip-archive URL the package directory is the *archive root*,
so this still lands the whole monorepo inside `Packages/`. It works only because
Sublime ignores folders it does not recognise, but it is untidy and is why
Option A is preferred.

## Sublime Merge

Nothing to prepare. Sublime Merge resolves themes by file name across all
packages, so `Merge.sublime-theme` inside a `Theme - Merge` folder is enough.
Document the copy step (see the root README) and stop there.

The folder name `Theme - Merge` is load-bearing: it must match the name of the
theme package Sublime Merge ships with, otherwise the bundled
`Theme - Merge.sublime-package` wins and the bundled light theme is what users
see. Renaming the folder — for example to `Tango - Merge` — would place the
package earlier in load order and silently break every color override.
